> git is a tool for tracking changes in files
> it is a distributed version control system used for tracking changes in files and coordinating work on projects among multiple developers

## it works in stages
> Local repository
This is an area where you make changes to your files

> Remote repository
This is an area where you store your files online so that anyone can access them

> LOCAL > STAGING > COMMIT > PUSH [STAGING OF CHANGES]

Git commands:

> git add <file_name> - adds a file to the staging area
> git add . - adds all files to the staging area
> git add * - adds all files to the staging area
> git add <folder_name> - adds all files in the folder to the staging area

> git status - shows the status of the files
> git status --short - shows the status of the files in a more concise format
> git show --name-only <commit_hash> - shows the files that were changed in the commit
> git show <commit_hash> - shows the changes made in the commit
> git log - shows the commit history
> git log --oneline - shows the commit history in a more concise format
> git log --graph - shows the commit history in a graph format
> git log --graph --oneline - shows the commit history in a graph format and in a more concise format

> git commit -m "message" - commits the changes to the local repository
> git commit -m "message" --amend - amends the last commit
> git commit --amend --no-edit - amends the last commit without changing the message
> git commit --amend --reset-author - amends the last commit and resets the author
> git commit --amend --reset-author --no-edit - amends the last commit and resets the author without changing the message

> git branch - shows all branches
> git branch <branch_name> - creates a new branch
> git branch -d <branch_name> - deletes a branch
> git branch -D <branch_name> - force deletes a branch
> git branch -m <old_branch_name> <new_branch_name> - renames a branch
> git branch -M <old_branch_name> <new_branch_name> - force renames a branch
> git branch -a - shows all branches (local and remote)
> git branch -r - shows all remote branches


>  git switch <branch_name> - switches to a branch
>  git switch -c <branch_name> - creates a new branch and switches to it
>  git switch - - switches to the last branch
>  git switch -d <branch_name> - deletes a branch
>  git switch -D <branch_name> - force deletes a branch

> git checkout <branch_name> - switches to a branch
> git checkout -b <branch_name> - creates a new branch and switches to it
> git checkout - - switches to the last branch
> git checkout -d <branch_name> - deletes a branch
> git checkout -D <branch_name> - force deletes a branch

> git diff branch1..branch2 - shows the differences between two branches
> git diff commit1 commit2 - shows the differences between two commits
> git diff --name-only commit1 commit2 - shows the names of the files that were changed between two commits

## difference between merge and rebase
> git merge <branch_name> - merges the branch with the current branch
> git rebase <branch_name> - rebases the branch with the current branch
> git rebase -i <branch_name> - interactive rebase
> git rebase --abort - aborts the rebase operation
> git rebase --continue - continues the rebase operation
> git rebase --quit - quits the rebase operation
the main difference is that merge creates a new commit while rebase does not

# git push
> git push -u origin <branch_name> - pushes the branch to the remote repository
> git push -f - force pushes the branch to the remote repository
> git push --delete origin <branch_name> - deletes a branch from the remote repository
> git push --delete origin <branch_name> --force - force deletes a branch from the remote repository

# git pull
> git pull - pulls the changes from the remote repository
> git pull origin <branch_name> - pulls the changes from the remote repository
> git pull --rebase - pulls the changes from the remote repository and rebases them

# git stashing helps when you want to switch branches but don't want to commit the changes
> git stash - saves the changes to a stash
> git stash list - shows the list of stashes
> git stash apply <stash_name> - applies the stash to the current branch
> git stash pop <stash_id/name>- applies the last stash to the current branch
> git stash drop <stash_name> - deletes a stash
> git stash clear - deletes all stashes

### Git cherry pick is used to select specific commits from one branch and apply them to another branch
> git cherry-pick <commit_hash> - applies a specific commit to the current branch
> git cherry-pick <commit_hash1> <commit_hash2> - applies multiple commits to the current branch
> git cherry-pick <commit_hash1>..<commit_hash2> - applies a range of commits to the current branch
> git cherry-pick --abort - aborts the cherry pick operation
> git cherry-pick --continue - continues the cherry pick operation
> git cherry-pick --quit - quits the cherry pick operation


### Git tags 
> git tag - lists all tags
> git tag <tag_name> - creates a tag
> git tag <tag_name> <commit_hash> - creates a tag for a specific commit

### Git squash means combining multiple commits into a single commit
> git squash <commit_hash> - combines the commits into a single commit
> git squash <commit_hash1> <commit_hash2> - combines multiple commits into a single commit
> git squash <commit_hash1>..<commit_hash2> - combines a range of commits into a single commit
> git squash --abort - aborts the squash operation
> git squash --continue - continues the squash operation
> git squash --quit - quits the squash operation
> git merge --squash <branch_name> - combines all commits from a branch into a single commit

### Git revert helps to undo changes that have been pushed to a remote repository
> git revert <commit_hash> - reverts a specific commit
> git revert <commit_hash1> <commit_hash2> - reverts multiple commits
> git revert <commit_hash1>..<commit_hash2> - reverts a range of commits
> git revert --abort - aborts the revert operation
> git revert --continue - continues the revert operation
> git revert --quit - quits the revert operation

### Git reset 
> git reset --hard HEAD~1 - resets the current branch to the previous commit
> git reset --soft HEAD~1 - resets the current branch to the previous commit but keeps the changes
> git reset --mixed HEAD~1 - resets the current branch to the previous commit but keeps the changes in the working directory
> git reset --hard <commit_hash> - resets the current branch to a specific commit
> git reset --soft <commit_hash> - resets the current branch to a specific commit but keeps the changes
> git reset --mixed <commit_hash> - resets the current branch to a specific commit but keeps the changes in the working directory
> git reset --hard origin/<branch_name> - resets the current branch to the remote branch
> git reset --soft origin/<branch_name> - resets the current branch to the remote branch but keeps the changes
> git reset --mixed origin/<branch_name> - resets the current branch to the remote branch but keeps the changes in the working directory
